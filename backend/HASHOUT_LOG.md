Decisions, reasons and anything left out, newest first. Code carries no comments; the context lives here. Started in 0.64.0; earlier history is not backfilled.

## 0.64.0 (2026-11-20): only FormSurface's own window can change things (`app/window_key.py`, `app/main.py`, `app/agent/router.py`, `formsurface_engine.py`)

- **The key.** `window_key.KEY` is made once per engine start with `secrets.token_urlsafe(32)`, kept in memory only and compared with `hmac.compare_digest`. Same design as FormVis and FormTools, under formsurface's names: header `x-formsurface-window-key`, sentence "Only the formsurface window can do this".
- **How the window gets it.** The desktop shell starts the engine with `FORMSURFACE_WINDOW_KEY_STDOUT=1`; the engine then prints `formsurface-window-key: <key>` once, before uvicorn prints the address, and `POST /api/window/key` answers 404. Started from source (no variable), the first page that calls `POST /api/window/key` gets the key and every later claim gets 409 and is recorded (`GET /api/window/key` says `secondClaim`).
- **Where it is needed.** `WindowKeyGuard` sits inside `LocalGuard` and refuses every request that is not GET, HEAD or OPTIONS without the key, with 403 and the sentence. The open list is `/api/agent` (the MCP relay, which only reaches the editor while the person has Agent link on) and the bootstrap. `/api/shutdown` is a POST added by the entry file and is covered by the same check, so the shell sends the key with it. The editor's live socket (`/api/live`) and the terminal socket (`/api/terminal/{sid}`) must send `{"type": "key", "key": ...}` as their first message within 5 s, or they are closed with 4403 before the live socket can replace the window that holds the relay. `GET /api/events` carries Chat and terminal events, so it needs the header or a one-time ticket from `POST /api/window/ticket` (an EventSource cannot set headers); a ticket lives 30 s and works once.
- **An agent tab** that sends its `x-formsurface-tab` header is still refused everywhere but `/api/agent`, as before; one that leaves the header out has no key and is refused by the guard with the sentence.
- **Left as it was.** `GET /api/chat/image` is a plain read of a file in the Chat folder by its full path, used as an image source; it does not take the key in this release. The Host and Origin guard stays unchanged; the key is an added layer.
- **The tests.** `tests/test_window_key.py`: every write operation in the OpenAPI list (plus `/api/shutdown`) answers 403 with the sentence with no key, a wrong key and a tab header; the bootstrap answers once, then 409, and is 404 in the shell's mode; a live client without the key is closed with 4403 and the linked window keeps the relay; a terminal socket without the key is closed with 4403 and one with it is served; the event stream needs the key or a ticket, and a ticket works once; an engine started here with the shell's variable prints the key line once before its address and tells the window (200), a program without the key, an agent tab with its header and a wrong key (each 403 with the sentence) apart, and refuses `/api/shutdown` without the key; an engine started from source prints no key and gives it once. The suite's `client` now sends the key, `bare` sends none, and the engine fixture claims the key the way the page does. 278 passed.
