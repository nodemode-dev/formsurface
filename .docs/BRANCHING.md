# Branching and releases

- `main` is always releasable. CI (`.github/workflows/ci.yml`: the editor's type check and build, the service's compile and boot, the wasm check of the engine, the service suite, the window smoke test and the script checks) must pass before anything lands. No force-push to `main`.
- Work happens on short branches cut from `main` and merged by pull request: `feat/[topic]`, `fix/[topic]`, `docs/[topic]` or `chore/[topic]`.
- Commits follow Conventional Commits with the version in the summary, `type(scope): summary (x.y.z)`, and a body that says what changed, why and what was run, for example `fix(editor): reserve the fps readout so the status bar does not shift (0.59.9)`. Scopes match the code: `engine`, `editor`, `shell`, `home`, `service`, `mcp`, `desktop`, `theme`, `i18n`, `scripts`, `tests`. Every commit has one author and committer, `nodemode-ai <mackin@nodemode.ai>`, with no attribution trailer.
- Versions are `v*.*.*` with dots, and the patch number is one digit (the service suite checks it). The version bump is the last commit of a release, `chore(release): vX.Y.Z`, and it changes every version site in one go: `VERSION`, the README version badge, the usage line in `formsurface`, `backend/app/main.py`, `frontend/package.json` and `frontend/package-lock.json`, `frontend/src/version.ts`, `native/Cargo.toml` and `native/Cargo.lock`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock` and `src-tauri/tauri.conf.json`, the version lines of the skills under `.claude/skills` and `.agents/skills` and of their `references/tools.md`, and a new `CHANGELOG.md` section. `backend/tests/test_f4_versions.py` fails when the sites listed in `backend/tests/conftest.py` disagree.
- Releases are built by formcompiler (`nodemode-dev/formcompiler`), not here. After the version bump lands on `main`, a maintainer pushes a branch `compile_vX.Y.Z` cut from that commit. CI runs on it, and formcompiler builds the macOS, Windows and Linux bundles and drafts `formsurface-vX.Y.Z` on its own release page. Compile branches are kept as the record of what was built.
- The wiki is edited only in `.docs/wiki`, never in the GitHub wiki UI; `.github/workflows/wiki.yml` publishes the folder when it changes on `main`. The wiki must have one page created by hand once before the first publish.
