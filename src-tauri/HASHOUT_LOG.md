## 0.66.0 (2026-11-20): the engine is held, and a failed start says why (`src/main.rs`, `src/engine_start.rs`, `src/win_job.rs`, `Cargo.toml`, `Cargo.lock`; `../setup/freeze_backend`, `../formsurface.bat` :freeze)

- The engine is still started through tauri-plugin-shell's `sidecar` (FormVis's and FormSculpt's way), so on Windows `win_job::hold_pid(child.pid())` puts it in a job object right after the spawn; the job ends the engine, and everything it started, when the app ends however it ends, and `kill_backend` also ends the job after the existing kill. `win_job.rs` is FormVis's file at origin/main, unchanged (its `hold` for a standard-library child is not used here). `windows-sys` 0.61 is a Windows-only dependency, already in `Cargo.lock` through Tauri at 0.61.2; the lock gains only the name in formsurface's own list.
- `engine_start.rs` is FormSculpt's file with formsurface's names: `ADDRESS_WAIT` 90 seconds (the owner's limit for every app; it replaces the two minute watchdog thread), the sentence for each failure, the last 12 lines the engine printed (never the window key line), and the log's path, `<data>/Logs/formsurface-engine.log`, with the data folder found as the engine finds it (`FORMSURFACE_DATA`, `~` read as home, else `~/FormSurface`). One difference: an empty `FORMSURFACE_DATA` makes the engine use its working folder, which the shell cannot know, so the shell names `~/FormSurface` then.
- `read_port` feeds every line to the tail and, after the engine ends, reads for `EXIT_WAIT` (1 second) more, so lines that arrive after the end are still shown. `start_failed` builds the text and calls `engine_failed`, which now shows the dialog first and closes the splash, the only window at that point, after the person has closed the dialog: closing the last window first could end the app before the dialog appeared. A main window that cannot be built now gives its own sentence instead of closing the splash without a word. The shell gives the engine its process id in `engine_start::SHELL_ENV`, `FORMSURFACE_PARENT_PID`, the name the engine watches today.
- The Windows engine is built with no console window: `freeze_backend` gives PyInstaller `--noconsole` when `fs_os` says windows and `FORMSURFACE_ENGINE_WINDOWED` is not `0`; its twin, the `:freeze` section of `formsurface.bat`, does the same through `FORMSURFACE_CONSOLE` (empty when `FORMSURFACE_ENGINE_WINDOWED=0`; the script's `setlocal` keeps it inside). `setup/desktop_build.bat` calls `formsurface.bat freeze` and `build_app` calls `setup/freeze_backend`, so both builds take it. No spec file is kept (`--specpath build/pyinstaller`). The engine's entry now replaces missing standard streams first (backend log), which a windowed engine needs.

Start FormSurface again; if this keeps happening, install it again.";`; `const ENGINE_SILENT: &str = "The FormSurface engine did not answer within two minutes. ## 0.64.0 (2026-11-20): the shell hands the window its key (`src/main.rs`)

- The engine is started with `FORMSURFACE_WINDOW_KEY_STDOUT=1`. The line reader takes the first `formsurface-window-key: ...` line (pattern `[A-Za-z0-9_-]{32,}`) and does not treat it as the address line. The main window is built with an initialization script that sets `window.__FORMSURFACE_WINDOW_KEY` only when the page's origin is the engine's own `http://127.0.0.1:<port>`, the same builder call as FormTools.
- On Windows the shell asks the engine to close with `POST /api/shutdown`, which now needs the key, so `Service` keeps the port and the key together and `ask_to_close` sends the header.
- Not compiled here; read against FormTools `src-tauri/src/main.rs` for every name and type. The orchestrator's shell check runs on the tip.
